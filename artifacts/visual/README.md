# Visual check output

Generated by `bash scripts/visual-check.sh`. It is regenerated on every run and
is not itself a source of truth — the script is.

## What a run covers

The wrapper starts the product on a temporary store, seeds it with toy fills, then
drives every view in the navigation in Chromium. For each view it records the DOM
size, the number of layout panels, whether the page overflows horizontally, and any
console error, and it writes a screenshot here.

`report.json` holds the machine-readable result: a per-view record plus a summary.

## Reading a result

```
OK   交易日志          dom=5049    panels=3   overflow=false  errs=0
```

- `overflow=true` means the page is wider than the viewport, which is how a
  dashboard breaks on a narrow window.
- `errs` counts console errors after filtering favicon and network noise.
- A view that fails to open reports `clicked=false` — that usually means the
  navigation label in `scripts/visual-check.cjs` no longer matches the label in
  `gui/src/App.tsx`. The two are kept in sync by hand, so a rename in the app
  needs the matching rename here.

The run exits non-zero unless every view is clean, so it works as a gate.

## What is not committed

`tmp-state/` and `*.png` are ignored: the first is a throwaway database, the
second is regenerated output. `server.log` is kept for diagnosing a failed run.
