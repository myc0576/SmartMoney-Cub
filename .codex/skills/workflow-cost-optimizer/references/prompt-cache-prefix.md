# 稳定前缀与状态外化规范 (Prompt Cache & State Externalization)

## 1. 为什么状态不能输出在会话历史里？

- 大模型会话是 Append-only 滚雪球。
- 如果每进入一个阶段（Wave 1 -> Wave 2），都在对话中打印完整任务看板、当前进度表格、数十行已完成项，这些文字将在后续几十轮中每一次都被重新打包计费。
- 解决办法：**状态外化到文件**。
  - 进度记录到项目文件（如 `ledger.md` 或 `progress.md`）。
  - 对话中只做单行轻量汇报（例如：`✅ Wave 1 完成 -> ������ Wave 2 启动`）。
  - 会话重置或唤醒时，读取文件立刻无缝恢复现场。

## 2. 稳定前缀设计 (Prompt Cache)

- 主流 LLM 服务商（Anthropic / OpenAI / DeepSeek 等）均支持 KV Cache / Prompt Cache，命中读取价格仅为正常计算的 10% 左右。
- 前提条件：请求的前缀必须严格保持一致。
- 规范：
  - **静态指令置顶**：系统角色、核心约束、安全红线始终位于最前端。
  - **动态参数后置**：具体任务描述、用户动态输入、当前临时文档放在请求末尾。
  - 不要把易变参数穿插在稳定模板指令中间。
